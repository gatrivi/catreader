# FEATURE #1 — SYNCED READING PROGRESS IS SACRED

```
NEVER EVER EVER PERSIST A TRANSIENT PAGE.

NEVER LET A UI REMOUNT (READER MODE, GHOST TEXT, ZOOM, THEME, OPEN/CLOSE)
REWRITE THE USER'S PAGE VIA INTERSECTIONOBSERVER AND THEN SAVE THAT LIE.

NEVER SAVE PROGRESS WHILE isRestoring / restoreTargetPage IS SET
(EXCEPT AN EXPLICIT FORCE SAVE ON CLOSE THAT USES THE FROZEN PAGE).

NEVER ACCEPT CLOUD PROGRESS THAT LOOKS LIKE A FALSE RESET TO PAGE 1–3
WHEN LOCAL (OR THE OTHER SIDE) WAS DEEP IN THE BOOK.

NEVER SET pageNumber=1 ON OPEN BEFORE loadProgress HAS SPOKEN.

IF YOU ADD A VIEW SWITCH OR DOM REMOUNT: FREEZE THE PAGE FIRST,
SCROLL BACK AFTER MOUNT, THEN CLEAR THE FREEZE. TEST IT.

FEATURE #1 = SYNCED PROGRESS. IF THAT BREAKS, THE APP IS BROKEN.
```

Code: `src/utils/progressGuard.ts`, `useReaderSync`, `App` toggle/open/close/observer.

Incident: v2.9.8 reader-mode → page ~3 clobber. Fixed v2.9.9+. Hardened v2.10.0.
